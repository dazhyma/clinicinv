# Критерии приёмки

Развёртка раздела 21 ТЗ в пошаговые проверки с конкретными числами. Каждый сценарий выполняется на чистом стенде с указанными исходными данными.

## Тестовые данные (общие для всех сценариев)

| Предмет | Внутренний код | Cost/unit | Начальный остаток | Ед. изм. |
| --- | --- | ---: | ---: | --- |
| Gauze 4×4 | `ITM-000127` | $3.00 | 10 | each |
| Gloves L | `ITM-000128` | $0.50 | 50 | pair |
| Syringe 10 mL | `ITM-000129` | $1.20 | 20 | each |
| Mask | `ITM-000130` | $0.25 | 100 | each |

| Пак | Код | Состав |
| --- | --- | --- |
| Basic Pack | `PCK-000015` | Gauze 4×4 ×2, Gloves L ×3, Syringe 10 mL ×1 |

Аккаунты: `staff` (роль Staff), `admin` (роль Admin).

# AC-1. Штрихкоды (§21.1)

## AC-1.1. Новый предмет автоматически получает уникальный код

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Войти как Admin, Inventory → Items → **Add New Item** | Форма открыта |
| 2 | Заполнить: Name = `Gauze 4×4`, Cost per Unit = `3.00`, Unit = `each`, Initial Quantity = `10`. Остальные поля пусты | Валидация проходит |
| 3 | Сохранить | Предмет создан. Присвоен `internal_code` вида `ITM-NNNNNN` (пример: `ITM-000127`). Поле непустое, формат соответствует §5.5 |
| 4 | Открыть карточку предмета | `In stock: 10 · Cost: $3.00`; кнопки **Edit** и **View Barcode** присутствуют |
| 5 | Создать второй предмет `Gloves L` | Присвоен **другой** код (`ITM-000128`). Коды не совпадают |
| 6 | Проверить остаток через журнал движений | Существует ровно одно движение с `quantity_delta = +10` (см. `state-machines.md` §2.2). `current_quantity = 10 = Σ quantity_delta` |

**FAIL, если:** код пуст, коды двух предметов совпали, формат не соответствует `ITM-NNNNNN`, остаток не равен сумме движений.

## AC-1.2. Код превращается в сканируемый штрихкод, View Barcode открывается отдельно

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Нажать **View Barcode** у `Gauze 4×4` | Открывается **отдельная страница или новая вкладка** (не модальное окно поверх списка) |
| 2 | Осмотреть страницу | Присутствуют: название `Gauze 4×4`, графический штрихкод, текстовый код `ITM-000127`, поле выбора количества копий, кнопка **Print** |
| 3 | Проверить отсутствие лишнего | На странице **нет**: навигационного меню, посторонних кнопок, фоновых элементов, карточки предмета, любых элементов не для этикетки |
| 4 | Отсканировать штрихкод с экрана/распечатки сканером клиники | Считанная строка **точно равна** `ITM-000127` |

## AC-1.3. Штрихкод печатается чётко

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Задать количество копий = `1`, нажать **Print** | В предпросмотре печати — одна этикетка, без навигации сайта |
| 2 | Задать количество копий = `5`, нажать **Print** | В предпросмотре ровно **5** одинаковых этикеток |
| 3 | Распечатать на обычном листе | Печать без размытия; под графическим кодом напечатана человекочитаемая строка `ITM-000127` |
| 4 | Отсканировать распечатку сканером | Считывается с первой попытки, результат `ITM-000127` |

## AC-1.4. Изменение названия и стоимости не меняет код

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Зафиксировать текущие `internal_code` = `ITM-000127` и значение штрихкода | — |
| 2 | Edit → Name = `Gauze 4x4 sterile`, Cost per Unit = `4.00`, SKU = `SKU-777`, Reference = `REF-123`, загрузить новое фото, изменить категорию, место хранения, порог, заметки. Сохранить | Все изменения сохранены |
| 3 | Проверить код и штрихкод | `internal_code` = `ITM-000127` (**не изменился**), значение штрихкода не изменилось, распечатанная ранее этикетка по-прежнему находит этот предмет при сканировании |
| 4 | Проверить форму Edit | Поля `internal_code` и `barcode_value` отсутствуют либо недоступны для редактирования |
| 5 | Отправить запрос на изменение `internal_code` в обход UI | Сервер отклоняет |

## AC-1.5. Два предмета не могут получить одинаковый код

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Создать 10 предметов подряд | Все 10 кодов различны |
| 2 | Запустить параллельное создание 20 предметов в 20 одновременных запросах | Все 20 кодов различны; ни один запрос не создал дубликат |
| 3 | Попытаться вставить в БД предмет с уже существующим `internal_code` напрямую | **Вставка отклонена ограничением базы данных** (не только логикой приложения) |
| 4 | То же для `barcode_value` | Отклонено ограничением БД |

## AC-1.6. Пак получает собственный уникальный код

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Создать `Basic Pack` | Присвоен код вида `PCK-000015`, сгенерирован штрихкод |
| 2 | Сравнить пространство кодов | Код пака не совпадает ни с одним кодом предмета; префиксы `ITM-` / `PCK-` различают сущности |
| 3 | **View Barcode** у пака | Отдельная страница с названием пака, штрихкодом и внутренним кодом пака |

# AC-2. Активная операция (§21.2)

## AC-2.1. Операция переживает refresh, закрытие браузера и logout

Исходные остатки: Gauze 10, Gloves 50, Syringe 20.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Войти как Staff → Operations → **Start New Operation** | Создана операция со случайным кодом (пример `K7P4Q`), статус **Active**. Запись **уже сохранена на сервере до первого скана** |
| 2 | Немедленно обновить страницу | Операция существует, статус Active, позиций 0 |
| 3 | Отсканировать `ITM-000127` три раза подряд, без кликов мышью между сканами | Все три скана зарегистрированы. Строка Gauze: количество **3**. Подтверждение вида `Gauze 4×4 added` каждый раз, зелёный индикатор. Поле сканирования остаётся активным |
| 4 | Отсканировать `ITM-000128` дважды | Строка Gloves L: количество **2** |
| 5 | Отсканировать `ITM-000129` один раз | Строка Syringe: количество **1** |
| 6 | Проверить состав | 3 уникальных позиции, 6 использованных единиц |
| 7 | Проверить остатки в Inventory | Gauze **7** (10−3), Gloves **48** (50−2), Syringe **19** (20−1) |
| 8 | **Обновить страницу (F5)** | Те же 3 позиции, количества 3 / 2 / 1, тот же итог, статус Active |
| 9 | **Закрыть браузер полностью**, открыть заново, войти как Staff | На странице Operations отображается блок: `Active operation found` / `Case: K7P4Q` / счётчик отсканированного / кнопка **Resume Operation** |
| 10 | Нажать **Resume Operation** | Восстановлены: полный список из 3 позиций, количества 3 / 2 / 1, зафиксированные цены $3.00 / $0.50 / $1.20, текущий итог **$11.20** (9.00 + 1.00 + 1.20). Поле сканирования снова готово |
| 11 | Выполнить **logout**, затем войти снова | Операция по-прежнему Active; позиции и количества не изменились; остатки Gauze 7 / Gloves 48 / Syringe 19 **не изменились** — на склад ничего не вернулось |
| 12 | Дождаться истечения срока сессии (или принудительно инвалидировать сессию), войти снова | Статус **Active**, `finished_at` пуст |
| 13 | Перезапустить серверный процесс, войти снова | Статус **Active**, состав идентичен |
| 14 | Проверить, что операция не завершилась сама | В журнале нет перехода статуса; `finished_at` и `voided_at` пусты; движений `returned_from_operation` не создавалось |

**FAIL, если:** после любого из шагов 8–13 изменился статус, пропала позиция, изменилось количество, изменился остаток или изменилась зафиксированная цена.

## AC-2.2. Исправления в активной операции корректируют остаток немедленно

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | В операции из AC-2.1 (Gauze ×3, остаток 7) нажать `−` один раз | Количество Gauze = **2**, остаток Gauze = **8**, создано движение `returned_from_operation` с `+1` |
| 2 | Обновить страницу | Количество 2, остаток 8 — сохранено |
| 3 | Нажать **Undo Last Scan** | Последнее действие откачено ⚠ (глубина и семантика Undo — см. `open-questions.md`); остаток изменён соответственно; изменение сохранено немедленно |
| 4 | Удалить строку Syringe | Строка исчезла, остаток Syringe = **20**, создано движение `returned_from_operation` с `+1` |
| 5 | Проверить итог операции | Итог уменьшен ровно на `quantity × unit_cost_snapshot` удалённых единиц |

## AC-2.3. Несколько активных операций сосуществуют

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | При наличии активной операции `K7P4Q` нажать **Start New Operation** | Показан список активных операций с кнопкой **Resume** у каждой и кнопкой **Start Another Operation** |
| 2 | Нажать **Start Another Operation** | Создана вторая операция с **другим** кодом; первая операция не изменилась: тот же код, тот же состав, тот же статус Active |
| 3 | Отсканировать предмет во вторую операцию | Изменилась только вторая операция; состав первой не затронут |
| 4 | Открыть блок активных | Обе операции видны, обе Active |

## AC-2.4. Проверка доступного количества

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Довести остаток Mask до **2** | — |
| 2 | В активной операции отсканировать Mask трижды | На третьем скане показано предупреждение вида **Only 2 units remain in inventory** |
| 3 | Проверить статус операции | Операция **не завершилась автоматически**; предупреждение не скрыто |
| 4a | В режиме «запретить превышение» | Третья единица **не** добавлена; количество Mask в операции = 2; остаток = 0 |
| 4b | В режиме «разрешить с предупреждением» (рекомендуемый по §7.10) | Третья единица добавлена; остаток стал **−1**; предупреждение отображается ярко |

# AC-3. Пак (§21.3)

Исходные остатки: Gauze **100**, Gloves **50**, Syringe **20**. Цены: $3.00 / $0.50 / $1.20.

## AC-3.1. Один скан добавляет весь состав

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Admin создаёт `Basic Pack`: Gauze ×2, Gloves ×3, Syringe ×1 | Пак сохранён, присвоен код `PCK-000015`, создан штрихкод |
| 2 | Проверить расчётную стоимость пака | `2×3.00 + 3×0.50 + 1×1.20` = **$8.70**. Поле ручного ввода итоговой стоимости отсутствует |
| 3 | Проверить, что у пака нет остатка | В карточке пака **нет** поля «в наличии» |
| 4 | Staff начинает операцию `O-PACK` и делает **один** скан `PCK-000015` | Подтверждение вида `Basic Pack added — 6 items` |
| 5 | Проверить состав операции | **3 строки**: Gauze ×2, Gloves ×3, Syringe ×1. Каждая помечена источником `pack` со ссылкой на `Basic Pack` |
| 6 | Проверить снимки стоимости | Gauze: unit $3.00, line **$6.00**; Gloves: unit $0.50, line **$1.50**; Syringe: unit $1.20, line **$1.20**. Итог операции **$8.70** |
| 7 | Проверить остатки | Gauze **98** (100−2), Gloves **47** (50−3), Syringe **19** (20−1) |
| 8 | Проверить движения | Ровно 3 движения `used_in_operation` с `−2`, `−3`, `−1`, все с `operation_id = O-PACK` |

## AC-3.2. Скан пака атомарен

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Смоделировать сбой при списании второй позиции пака | Операция **не содержит ни одной** строки этого скана; остатки Gauze / Gloves / Syringe **не изменились**; пользователь видит понятную ошибку |
| 2 | Проверить журнал движений | Ни одного частичного движения по этому скану не создано |

**FAIL, если:** списана половина пака.

## AC-3.3. Изменение состава пака не меняет завершённую операцию

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Завершить операцию `O-PACK`: **Finish Operation** → **Finish and Lock** | Статус **Finished**, `total_cost_snapshot` = **$8.70** |
| 2 | Admin меняет состав `Basic Pack`: Gauze ×2 → **×4**, добавляет Mask ×1 | Пак сохранён; расчётная стоимость пака стала `4×3.00 + 3×0.50 + 1×1.20 + 1×0.25` = **$14.95** |
| 3 | Открыть завершённую операцию `O-PACK` | **По-прежнему 3 строки**: Gauze **2** (не 4), Gloves 3, Syringe 1. Mask отсутствует. Итог **$8.70** (не $14.95) |
| 4 | Проверить остатки после редактирования пака | Остатки **не изменились** (Gauze 98, Gloves 47, Syringe 19). Редактирование пака не порождает движений |
| 5 | Начать новую операцию и отсканировать `PCK-000015` | Добавлено **4 строки**: Gauze ×4, Gloves ×3, Syringe ×1, Mask ×1. Остатки уменьшены на 4 / 3 / 1 / 1 |

## AC-3.4. Предмет в нескольких паках и отдельно

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Создать второй пак `Extra Pack` c Gauze ×1 | Оба пака содержат Gauze |
| 2 | В одной операции отсканировать `Basic Pack`, затем `Extra Pack`, затем `ITM-000127` отдельно | Остаток Gauze уменьшен суммарно на `2 + 1 + 1 = 4`. В карточке операции видно, какие количества пришли от какого пака, а какие — отдельным сканом |

# AC-4. Стоимость (§21.4) — канонический пример $3.00 / $4.25

Исходно: Gauze 4×4, `current_unit_cost` = **$3.00**, остаток 10.

## AC-4.1. Снимок стоимости в завершённой операции

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Staff начинает операцию `O-COST` | Статус Active |
| 2 | Добавить Gauze 4×4 в количестве **2** (два скана) | Строка: `unit_cost_snapshot` = **$3.00**, `quantity` = 2, `line_total` = **$6.00**. Также сохранены снимки названия, внутреннего кода, SKU и reference number на момент добавления |
| 3 | Проверить остаток | Gauze = **8** |
| 4 | **Finish Operation** → **Finish and Lock** | Статус **Finished**, `total_cost_snapshot` = **$6.00** |
| 5 | Admin: Edit Gauze 4×4 → Cost per Unit = **$4.25**. Сохранить | Карточка предмета показывает **$4.25** |
| 6 | Открыть завершённую операцию `O-COST` | Строка Gauze: unit cost **$3.00**, quantity 2, line total **$6.00**. Итог операции **$6.00**. **Не $8.50** |
| 7 | Обновить страницу, перезайти | Значения те же: $3.00 / $6.00 |
| 8 | Начать **новую** операцию, добавить Gauze ×2 | `unit_cost_snapshot` = **$4.25**, `line_total` = **$8.50** |

**FAIL, если:** завершённая операция показала $4.25 или $8.50; итог пересчитался; изменение цены породило UPDATE строк истории.

## AC-4.2. Изменение цены не трогает уже добавленные строки активной операции

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | При цене $3.00 создать операцию `O-LIVE` и добавить Gauze ×1 | Строка: unit **$3.00**, line **$3.00** |
| 2 | Admin меняет цену Gauze на **$4.25** | Карточка предмета: $4.25 |
| 3 | Открыть/обновить `O-LIVE` (операция всё ещё Active) | Строка Gauze **по-прежнему** unit $3.00, line $3.00. Самопроизвольного пересчёта нет |
| 4 | Удалить строку Gauze и добавить её заново | Новая строка: unit **$4.25**, line **$4.25** |
| 5 | Добавить в ту же операцию ещё одну единицу Gauze | Применяется цена, действующая на момент добавления, — **$4.25** |

## AC-4.3. Изменение атрибутов предмета не пересчитывает историю

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Открыть завершённую `O-COST`, зафиксировать снимки: name = `Gauze 4×4`, SKU, reference | — |
| 2 | Admin меняет name → `Gauze 4x4 sterile`, SKU → `SKU-999`, reference → `REF-999` | Карточка предмета обновлена |
| 3 | Открыть `O-COST` снова | Строка показывает **старые** снимки: `Gauze 4×4`, прежние SKU и reference. Итог **$6.00** |

## AC-4.4. Стоимость пака следует за текущими ценами, история — нет

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | При цене Gauze $3.00 расчётная стоимость `Basic Pack` = **$8.70** | — |
| 2 | Изменить цену Gauze на $4.25 | Расчётная стоимость `Basic Pack` стала `2×4.25 + 3×0.50 + 1×1.20` = **$11.20** |
| 3 | Открыть завершённую операцию `O-PACK` из AC-3 | Итог **$8.70** — не изменился |

# AC-5. Void (§21.5) — канонический пример 10 → 8 → 28 → 30

Это ключевой сценарий приёмки. Исходно: Gauze 4×4, остаток **10**, цена **$3.00**.

## AC-5.1. Возврат ровно списанного количества

| Шаг | Действие | Тип движения | `quantity_delta` | Остаток Gauze | Прочие проверки |
| --- | --- | --- | ---: | ---: | --- |
| 0 | Исходное состояние | — | — | **10** | — |
| 1 | Staff создаёт операцию `O-VOID`, сканирует Gauze **2** раза | `used_in_operation` ×2 | −1, −1 | **8** | Строка: unit $3.00, qty 2, line $6.00 |
| 2 | **Finish Operation** → **Finish and Lock** | — | — | **8** | Статус Finished, `total_cost_snapshot` = **$6.00** |
| 3 | Admin: **Receive Stock** Gauze, количество **20** | `received` | +20 | **28** | Поставка учтена |
| 4 | Admin открывает `O-VOID`, нажимает **Void Operation** | — | — | **28** | Диалог: `Void Operation ...? / All inventory deducted by this operation will be returned. / The operation will be excluded from financial totals. / [Cancel] [Void Operation]` |
| 5 | Нажать **Cancel** | — | — | **28** | Ничего не изменилось; статус по-прежнему Finished |
| 6 | Снова **Void Operation** → подтвердить | `void_reversal` | **+2** | **30** | Статус **Voided**, `voided_at` заполнен |

### Обязательные проверки после шага 6

| # | Проверка | Ожидаемое значение |
| --- | --- | --- |
| 1 | Остаток Gauze | **ровно 30** |
| 2 | Остаток **не равен** 10 | ✔ старый общий остаток не восстановлен (§10.3, §18.20) |
| 3 | Остаток **не равен** 12 | ✔ |
| 4 | Остаток **не равен** 32 | ✔ возврат не применён дважды |
| 5 | Движение `received +20` | сохранено, поставка остаётся учтённой |
| 6 | Количество движений `void_reversal` по `O-VOID` | ровно **1** на предмет |
| 7 | Статус `O-VOID` | **Voided**, видна в истории аннулированных (Admin) |
| 8 | Строки операции | сохранены: Gauze ×2 @ $3.00, line $6.00 |
| 9 | Финансовый итог за период | уменьшен на **$6.00** — операция исключена из обычных финансовых итогов |
| 10 | `O-VOID` в блоке активных | отсутствует |
| 11 | `Item.current_quantity` vs Σ движений | `10 (initial) − 1 − 1 + 20 + 2 = 30` ✔ инвариант держится |
